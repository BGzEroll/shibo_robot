# gain_poly 与力矩链路

## 旧系数为什么不能直接复制

核对旧项目 `origin/main`：电机通过 `BLDCMotor(7, 12.27166f, 100.0f)` 初始化，使用 SimpleFOC 2.2.3 的电压力矩模式，并将 LQR 输出直接传给 `move()`。该版本在提供相电阻时执行 `Uq = target * phase_resistance + voltage_bemf`，因此目标实际按估算电流解释，而非 N·m。参见 [SimpleFOC 2.2.3 源码](https://github.com/simplefoc/Arduino-FOC/blob/v2.2.3/src/BLDCMotor.cpp)。

新 FOC 的接口是物理目标力矩：

```text
Iq_est = torque_Nm / kt_Nm_A
Uq = phase_resistance_ohm * Iq_est + ke_V_s_rad * shaft_speed_rad_s
uq_Q15 = Uq / measured_bus_voltage_V * 32768
```

没有电流采样，所以这仍是电压模型下的力矩估计，不是闭环电流控制。`Kt` 必须采用与这个公式对应的有效转矩常数，不能直接将任意 KV 换算公式中的 RMS/峰值、线电压/相电压常数混用。

原样把旧目标数值改解释为 N·m，会改变输出量纲。当前重构开始时的 `0.1*(2/3)` 是临时比例，不能作为物理标定结论；新代码删除了这段硬编码，保留可配置 `torque_scale` 作为显式调试比例，默认 1。电机接口改为 μN·m，避免原整数 mN·m 在小力矩下的阶梯量化。

FOC 仍使用固定 7 极对、3 V 对齐电压和编码器方向/零位校准。网页的单相电阻默认 12.27166 Ω、Kt/Ke 默认 0.0796；这些是源代码中的起始值，尚未得到本次实机标定。母线电压直接采用 battery 的 ADC 校准测量值，分压换算比例为 3.97，不再通过网页配置。motor 每 50 ms 更新校准、力矩和反电动势换算系数，校准与运行共用此电压来源；启动最多等待 1 秒，测量无效或为零时禁止输出。若星形电机量得的是线间电阻，单相电阻通常取一半，先确认接法及测量定义。

Q15 输出最大值为 18919，即约 `Vbus/√3` 的 q 轴电压。忽略反电动势时，以默认电机参数和 7.4 V 母线估算静态最大力矩约 0.0277 N·m；速度升高后可用余量会下降。默认单轮目标限幅 0.025 N·m。应先核对供电、R、Kt、Ke 和输出方向，再调整模型权重，不能用扩大 gain_poly 掩盖反馈或换算错误。

## 原 MATLAB 脚本的边界

`../matlab/K矩阵计算/wip_lqr_gain_scheduling.m` 计算的是连续 LQR，状态为 `[θ, θ̇, x, ẋ, δ, δ̇]`。它按左轮、右轮输出 K，没有包含固件执行反馈所需的负号，也未采用当前固件的速度误差积分状态。因此该脚本的打印结果不能直接粘入固件。

脚本中的 `m=2*0.0594` 与动力学方程 `M+2*m` 的单轮质量含义不一致；惯量拟合目录则分别保存了质心惯量 Jc 和轮轴惯量 Jo。旧调度式中接近 `0.3*L²` 的惯量项，与方程另外加入 `M*L²` 的写法需要区分，否则存在重复计算平行轴项的问题。旧脚本的采样范围 0.03–0.1 m 与旧固件夹紧范围 0.02–0.06 m 也不一致。

原始文件保留作为参考，新生成入口是 `../matlab/K矩阵计算/wip_gain_export.m`。它直接针对当前反馈状态求解，明确使用每轮 0.0594 kg、CAD 的 Jc 数据、1 ms 零阶保持离散模型和物理轮力矩。CAD 数据的质量假设也应与实际机身质量核对。

## 新状态和方向

固件执行 `torque = gain * feedback`，反馈顺序固定为：

| 列 | 状态 | 单位 |
| --- | --- | --- |
| 0 | 俯仰角减零偏 | rad |
| 1 | 俯仰角速度 | rad/s |
| 2 | 轮线速度减滤波速度参考 | m/s |
| 3 | 偏航角速度减滤波偏航参考 | rad/s |
| 4 | ∫(速度参考−轮线速度)dt | m |
| 5 | ∫(偏航参考−偏航角速度)dt | rad |

两行按左、右排列，各状态的四个系数依次为 `[h³,h²,h,1]`，高度单位 m。参考值使用一阶滤波，积分有限幅；目标力矩饱和时停止继续扩大积分。起身阶段只采用俯仰反馈并平滑恢复输出；跳跃阶段按动作需要开关速度/偏航反馈。

控制、动作和 MATLAB 的左右轮力矩均以前进为正，生成器的偏航输入采用右正/左负产生正 IMU 偏航的约定。俯仰仍直接使用 IMU Y 轴，偏航使用 IMU Z 轴；真实 IMU 安装方向和 Kt 必须验证，不能用 LQR 权重修补坐标错误。

`config.h` 的 `left_wheel_direction`、`right_wheel_direction` 分别指定左右轮前进方向：1 表示正 FOC 力矩使小车前进，-1 表示负 FOC 力矩使小车前进。两项默认 -1，网页电机分组可分别修改，保存并重启生效。自动校准的编码器方向只用于把编码器计数转换到 FOC 坐标，不代表车体前进方向。

`control.cpp` 同时转换速度反馈和输出力矩：`ω前进 = 车轮方向 × 编码器校准方向 × ω原始`，`v = r × (ω左前进 + ω右前进) / 2`，`τFOC = 车轮方向 × τ前进`。调整安装方向配置不需要重新生成增益，FOC 内部的电角度、零位和反电动势计算保持原有坐标。

本次将原 FOC 输入模型 B 和默认增益 G 同时整体取反，坐下的直接力矩改为正 0.005 N·m。默认两轮方向 -1 时，轮速反馈和最终 FOC 力矩与转换前一致。此前保存到 NVS 或导出的 gain_poly 仍是原 FOC 坐标，使用新固件前应在网页载入新默认值或导入新的候选增益并保存；不自动转换旧系数。

腿舵机计数拟合首先表示腿部几何高度，未必等于模型的质心到轮轴距离。默认 `height_feedback=false`，模型高度 0.048 m；实测后设置 `height_com_scale` 和 `height_com_offset_m`，再开启高度反馈。增益调度范围固定在生成器采样范围 0.031–0.082 m，固件在范围外夹紧。范围外夹紧不代表该实际姿态的模型稳定性已经验证。

## 生成和调参

MATLAB 中执行：

```matlab
cd('/home/bgzerol/embedded_project/shibo_robot/matlab/K矩阵计算')
wip_gain_export
```

需要 Control System Toolbox，生成 `gain_poly_candidate.json`，可直接导入网页。输出采用明确的左右轮/状态/系数嵌套向量。MATLAB `jsonencode` 的数组/嵌套向量规则见 [官方说明](https://www.mathworks.com/help/matlab/ref/jsonencode.html)。当前环境没有 MATLAB，仓库候选 JSON 和固件默认系数由 `tests/check_lqr.py` 使用 SciPy 独立复算得到；未声称在 MATLAB 本身执行过。

新权重按允许偏差设置：俯仰 5°、角速度 150°/s、线速度 0.30 m/s、偏航速度 2 rad/s、线积分 0.08 m、偏航积分 0.30 rad，允许输入力矩 0.020 N·m。Q 为各偏差平方倒数，R 为两轮单位阵除以允许力矩平方。需要更改模型设计时修改脚本中的这些明确数值，再导出，而不是逐个猜 48 个多项式系数。

在 0.048 m，高度反馈矩阵约为：

```text
L [0.235025, 0.015965, 0.121996,  0.008052, -0.169837, -0.046103]
R [0.235025, 0.015965, 0.121996, -0.008052, -0.169837,  0.046103]
```

1001 个高度点、float32 系数/Horner 运算的离散线性闭环最大极点模为 0.998332154；三次拟合最大绝对增益误差约 0.000235。此结果只覆盖理想模型及假定的力矩实现，不包含电压饱和、电机电感、摩擦、轮胎打滑、供电跌落、采样延迟和跳跃接触变化。

实机调参顺序：先可靠地读取编码器/IMU，确认 R/Kt/Ke/供电和低力矩输出方向；再确认俯仰与偏航反馈方向、固定质心高度下的平衡；随后验证速度/偏航参考与积分；最后标定高度反馈、验证坐下/跳跃/视觉动作。阶段之间一次只改变一组参数，分别保留稳定的配置 JSON。本次没有执行这些实机步骤或烧录。
