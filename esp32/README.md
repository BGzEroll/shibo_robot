# SHIBO ESP32

固定硬件的 ESP-IDF 6.0.2 实现，开发分支为 `test`。ESP32 负责轮电机 FOC、平衡和腿部动作；保留 Xbox 与上位机输入，网页提供状态和参数配置。

## 启动与操作

上电会进行轮电机方向/零位校准，校准完成后等待遥控输入。扶正小车，手柄收到有效输入后重新按 RB 起身；Start 停止轮电机并关闭腿舵机扭矩。跌倒、反馈过期或遥控失联后，需要恢复反馈、扶正并重新按 RB。

| 输入 | 功能 |
| --- | --- |
| 右摇杆上下 | 前进/后退 |
| 左摇杆左右 | 转向 |
| 方向键上下 | 腿部高度 |
| 方向键左右 | 横滚目标 |
| LS | 平衡时复位腿部姿态；坐下时释放腿扭矩 |
| LB | 坐下 |
| 坐下后 RB | 起身；低电时禁止起身 |
| 坐下后 Select + LB | 释放腿扭矩，等待 2 秒后校准两侧中位 |
| RS | 原地跳 |
| Y / A / X / B | 向前跳 / 向后跳 / 左转跳 / 右转跳 |
| Select + X / Y | 原地视觉踢球 / 追球踢球 |
| 踢球时 Select + B | 退出踢球 |
| 平衡时 Select + B | 重置平衡参考和积分 |
| Select + 方向键上下 | 摄像头角度 |

Xbox 优先于上位机。Xbox 连接成功时提供一次振动反馈。连接或输入来源切换时丢弃历史按键事件，避免按住 RB 重连后直接启动。低电时，平衡模式自动进入坐下流程；电压恢复后才允许起身。

## 参数网页

连接热点 `SHIBO_ROBOT`，密码 `12345678`，访问 `http://192.168.4.1`。填写 Wi-Fi 名称/密码后，下次启动同时连接该网络，配置热点继续保留；STA 地址通过串口启动日志显示。

网页可编辑 `gain_poly`、轮半径、质心高度、俯仰零偏、速度参考滤波、积分限幅、电机 R/Kt/Ke/母线电压/力矩限幅、最大速度、横滚 PID、电池阈值，以及腿长/质心高度映射。手柄处于配对模式时会自动扫描 Xbox，网页显示 MAC；地址留空时自动选择扫描到的 Xbox，也可填写固定 MAC 后保存。

参数以 JSON 存在 NVS。先用 Start 停止，再点击“保存并重启”；一组配置在重启后统一生效，重启后仍需 RB 起身。支持导入完整配置或 MATLAB 的局部增益配置，导入本身只修改表单。JSON 导出含 Wi-Fi 密码。

| 接口 | 内容 |
| --- | --- |
| `GET /` | 参数页面，已嵌入固件 |
| `GET /api/config` | 当前完整配置 |
| `GET /api/defaults` | 编译时默认配置 |
| `GET /api/status` | 动作/使能/目标力矩/电池/视觉/手柄扫描状态 |
| `POST /api/config` | 校验并保存；运行中返回 409，成功后重启 |

## 固定硬件与任务

| 设备 | 配置 |
| --- | --- |
| 左/右轮 PWM | GPIO32/33/25、GPIO26/27/14，20 kHz MCPWM |
| 左/右轮 EN | GPIO22、GPIO12 |
| 左侧 AS5600 I²C | SDA19、SCL18 |
| 右侧 AS5600/MPU6050 I²C | SDA23、SCL5 |
| 腿 STS3032 | UART2，TX17/RX16，1 Mbaud，ID 1/2 |
| 摄像头/挡板 PWM 舵机 | GPIO4、GPIO15，LEDC 50 Hz，540–2600 μs |
| 电池 | GPIO35，ADC1_CH7，分压比 3.97 |
| 状态灯 | GPIO13；GPIO21 两颗 WS2812，RMT |
| 上位机/视觉 | UART0，TX1/RX3，115200 baud；也用于启动日志/固定监视屏 |

`motor` 在 core 1 由 PWM 通知执行 FOC；`control` 在 core 0 每 1 ms 平衡、每 10 ms 更新输入和动作。腿总线有独立任务，每 10 ms 写变化的目标、每 20 ms 读反馈，控制任务和监视屏读取快照。电池/灯效、UART0、BLE 扫描各有低优先级任务。网页使用 IDF HTTP Server，参数使用 NVS，BLE 使用原生 NimBLE/HID Host。

编码器 5 ms、IMU 15 ms、腿反馈 100 ms、遥控输入 250 ms 为有效期；电机命令超过 20 ms 也由 FOC 层关闭输出。腿高度调度默认关闭，使用固定 0.048 m；完成质心高度映射核对后可在网页开启。详细模型假设和力矩换算见 [LQR 调参说明](docs/lqr_tuning.md)。

## 上位机协议

帧格式为 `FF AA CMD LEN PAYLOAD CHECKSUM`，整数均为小端。

- `CMD=01`、`LEN=14`：`uint16 buttons`，随后 6 个 `int16` 轴值，轴值除以 1000。轴顺序为左横/左纵/右横/右纵/LT/RT；右纵控制行驶，左横控制转向。摇杆范围 −1000 至 1000，扳机 0 至 1000。校验只对 PAYLOAD 求 8 位和。
- `CMD=02`、`LEN=4`：`int16 dx, dy`，视觉像素偏差；任一值为 32767 表示无目标。校验对头部至 PAYLOAD 的全部字节求 8 位和。350 ms 没有新视觉帧时取消自动追球/瞄准，保留手动输入。

按键位依次为 A、B、X、Y、Share、Start、Select、Xbox、LB、RB、LS、RS、上、左、右、下。串口输入使用同一组动作映射。UART0 的日志属于发出方向，视觉与遥控帧从接收方向进入；注意与 USB 转串口的硬件连接关系。

## 构建与验证

```sh
# 使用本机已安装环境，其他机器激活自己的 ESP-IDF 6.0.2 即可。
source /home/bgzerol/.espressif/tools/activate_idf_v6.0.2.sh
idf.py build
sh tests/run_host.sh
python tests/check_lqr.py  # 需要 numpy、scipy
```

`sdkconfig.defaults`、分区表和 cJSON 依赖清单已经纳入项目；应用分区为 2 MiB。主机回归覆盖动作时序、输入边沿/过期、视觉丢失、参数导入/保存边界及 IMU 过期停机。LQR 数值验证覆盖 float32 系数的 1001 个高度点。

这些检查是源代码、主机模型和构建验证；没有烧录，也没有验证实际 BLE 配对、Wi-Fi/FOC 共存时序、轮电机力矩、腿部动作或视觉硬件效果。仓库中的默认增益是模型候选值，不能视作实机调试完成。
